# podori

**보안 점검부터 수정, 테스트까지 평소 쓰던 AI 에이전트로.**

한국어 안내 | [English](README.en.md) · `1.0.0`

podori(포돌이)는 AI 코딩 에이전트용 보안 스킬 모음입니다. 무엇을 점검하고 어떻게 고칠지, 수정 뒤에 무엇을 확인할지에 대한 기준과 절차를 제공합니다.

점검만 필요하면 코드와 근거를 살펴봅니다. 수정을 맡기면 보안 문제와 정상 기능을 함께 검증하도록 안내합니다. 점검 절차를 긴 프롬프트로 작성하지 않아도 프로젝트에서 스킬을 호출해 시작할 수 있습니다.

[시작하기](#시작하기) · [스킬 고르기](#필요한-스킬-고르기) · [검증 결과](#검증-결과)

## 시작하기

`skills/podori/` 폴더 전체를 사용하는 에이전트의 스킬 경로에 복사합니다. `SKILL.md`와 함께 `references/`, `templates/`도 필요합니다. 설치 경로는 에이전트의 안내를 따릅니다.

슬래시 호출을 지원하는 에이전트라면 대상 프로젝트에서 다음처럼 시작합니다.

```text
/podori
```

에이전트가 코드와 설정, 기존 테스트를 읽고 점검 범위를 정합니다. 필요한 수정과 테스트는 허용된 범위에서 진행하며 대상이나 승인 범위가 불분명할 때만 묻습니다.

코드를 바꾸지 않고 점검만 받고 싶다면 함께 요청합니다.

```text
이번에는 보안 문제만 점검하고 파일은 수정하지 마세요.
```

## 무엇을 맡길 수 있나요?

### 코드에서 문제를 찾고 근거를 확인합니다

관리자 버튼을 숨겨도 API까지 잠기지는 않습니다. 인증과 권한 검사가 실제 요청 경로에서 이루어지는지 살펴보고 입력값 처리, 파일 업로드, 비밀값 관리도 확인합니다. 소스로 확인한 문제와 실행 환경을 더 살펴봐야 하는 항목은 구분합니다.

### 필요한 부분을 고치고 정상 기능도 확인합니다

권한 검사를 고쳤다면 무단 요청이 막히는 것뿐 아니라 정상 사용자의 요청도 처리되는지 확인해야 합니다. 기존 코드 컨벤션에 맞춰 수정하고 대상 프로젝트의 실제 테스트로 보안 조건과 정상 동작을 함께 검증하도록 안내합니다. 별개의 개선 사항은 이번 수정과 분리합니다.

### 끝낸 일과 남은 일을 설명합니다

보고서는 확인한 문제와 수정·검증 결과, 다음에 필요한 작업을 정리합니다. 점검만 요청하면 소스 검토와 결과 보고로 마치고, 수정을 맡기면 테스트 결과까지 함께 설명합니다.

## 필요한 스킬 고르기

각 스킬은 독립적으로 동작합니다. 필요한 스킬만 설치할 수 있으며 하나를 호출한다고 다른 스킬까지 실행하지 않습니다.

| 맡길 일 | 스킬 | 호출 예시 |
|---|---|---|
| 앱·웹의 보안 코드 리뷰, 취약점 수정, 회귀 테스트 | [podori · 보안](skills/podori/SKILL.md) | `/podori` |
| 전자정부프레임워크 시큐어코딩과 정부 보안약점 기준 점검 | [podori-egov · 전자정부 보안](skills/podori-egov/SKILL.md) | `/podori-egov` |
| 패키지와 컨테이너 이미지의 출처·공급망 보안 점검 | [podori-doubt · 의심](skills/podori-doubt/SKILL.md) | `/podori-doubt` |
| 미끼와 함정 구현, 무단 탐색 흔적 확인 | [podori-trap · 함정](skills/podori-trap/SKILL.md) | `/podori-trap` |
| 동봉한 합성 앱의 수정 전후 동작을 샌드박스에서 비교 | [podori-wreck · 샌드박스 검증](skills/podori-wreck/SKILL.md) | `/podori-wreck` |

## 검증 결과

자체 평가에서는 대규모 기업 업무 시스템의 소스 발췌와 합성 Next.js 샘플을 사용했습니다. 모델의 소스 점검 결과, 패키지 정합 검사, 합성 앱 실행 테스트는 구분합니다.

## 만든 배경

최근 소속 팀에서 수십 개 저장소에 흩어진 Node.js, Python, Java, nginx 등의 취약점을 패치했습니다. 그 과정에서 정리한 점검 항목과 수정·검증 절차를 다른 개발자도 활용할 수 있도록 공유합니다.

## 작업 범위와 안전 기준

- **요청한 범위 안에서 작업합니다.** 일반 기능 개발을 전체 보안 감사로 확대하지 않습니다. 유효한 기존 근거는 재사용하고 변경된 부분과 영향받는 경계를 다시 확인합니다.
- **반복에 한도를 둡니다.** 기본 30분, 필수 항목별 최초 포함 최대 2회, 전체 수정·재검토 최대 두 차례입니다. 사용자가 지정한 다른 유한 예산이나 더 엄격한 호스트 제한을 따릅니다. 위임·보고서 갱신으로 예산을 초기화하지 않습니다. 근거 없는 반복이나 한도 초과 시 새 작업을 멈추고 남은 항목을 설명합니다.
- **실행 권한을 넘지 않습니다.** 승인·격리 조건이 없으면 해당 실행을 멈춥니다. 독립적으로 가능한 점검은 계속합니다. 운영 변경에는 별도 승인이 필요합니다.
- **폐쇄망에서도 준비된 근거를 사용합니다.** 에이전트·모델·도구·의존성을 미리 준비합니다. 작업 중 자동 설치·교체는 하지 않습니다. 권고 자료 수집·갱신은 별도 승인 작업이며 자료가 없거나 오래됐다면 미검증으로 남깁니다.

`podori`, `podori-egov`, `podori-doubt`는 CVSS v4.0을 사용하며 점수 근거가 부족하면 미평가로 남깁니다. 심각도는 실행 승인을 대신하지 않습니다. 스킬은 에이전트가 따르는 지침이며 시간·토큰 한도의 강제 적용과 컨텍스트 격리는 호스트 기능이 필요합니다.

## 설치본 갱신

릴리스 태그 `v1.0.0`을 기준으로 기존 설치본을 백업하고 선택한 스킬 폴더 전체를 교체합니다. `SKILL.md`의 버전과 파일 구성을 함께 확인합니다.

1.x에서는 다섯 스킬의 이름과 독립 사용, 승인·격리·완료 기준의 의미를 유지합니다. 자연어 보고서 표현과 탐지 결과, 내부 참조 경로는 고정 인터페이스가 아닙니다. 선택형 MCP의 도구·입력·승인 계약은 [MCP 호환 안내](mcp/README.md#1x-호환-계약)를 따릅니다. 호환되지 않는 계약 변경은 새 주 버전으로 구분합니다.

보안 기능은 대상 프로젝트에 코드를 적용한 뒤 실제 실행 환경에서 검증합니다.
